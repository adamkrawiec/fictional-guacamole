description: backbone for additions or editions happening in github workflow

When a prompt, or a feature, requires a new github action, do changes to the gtihub action first, ahead of any coding.
This is to be able to observe, in a case of a failure, was the root cause in the code, or the workflow broken.
After a workflow was added, compare with exsiting workflows and see, if there is any repetion that could be cleaned up.
